= NetApp Consoleの導入モードについて学ぶ
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
NetApp Console は、SaaS アプリケーションを介して使用することも、独自の環境（クラウドまたはオンプレミス）にインストールすることもできます。

NetApp では、これらのユースケースを_デプロイメント モード_と呼びます。各モードでは、ビジネスとセキュリティのニーズに合わせて、さまざまな接続性、機能、サービスが提供されます。

標準モード（SaaS）:: NetApp Console SaaS（ソフトウェア・アズ・ア・サービス）アプリケーションは、すべてのNetAppデータサービスへのアクセス、自動アップデート、アイデンティティフェデレーションやNetApp Support Siteログインなどの柔軟な認証オプションを可能にします。このモードはマーケットプレイスサブスクリプションおよびBYOLライセンスに対応しています。このモードは、特にNetApp Consoleで利用可能な最も多くの機能やサービスを求めるユーザや組織に最適です。
制限モード（独自のパブリック クラウドにインストール）:: 制限モードは、政府機関や規制対象の企業など、セキュリティの強化と接続の制限を必要とする組織向けです。NetApp Console を独自のパブリック クラウド（政府、主権、または商業地域）にインストールすると、NetApp Console API エンドポイント（SaaS アプリケーションでホスト）への外部接続が制限されます。制限モードでは、Cloud Volumes ONTAP、Azure NetApp Files、NetApp Backup and Recovery（政府および商業地域）、データ分類などの主要なデータ サービスと、自動化されたソフトウェア アップグレードおよび ID フェデレーションにアクセスできます。
プライベートモード（オンプレミスまたはクラウドにインストール）:: プライベート モードは、AWS Secret Cloud、AWS Top Secret Cloud、Azure IL6、エアギャップ環境などの厳格なセキュリティ ニーズを持つ組織向けです。NetApp Console SaaSアプリケーションやNetAppクラウドベースのAPIには接続せず、完全な制御が可能になり、外部との通信をブロックできます。サポートされているデータ サービスには、NetApp Backup and Recovery、NetApp Data Classification、NetApp Replication、Cloud Volumes ONTAPが含まれます。すべてのストレージと認証はローカルのままであり、データは環境内に保持されます。このモードは、防衛請負業者、厳格なデータ保存規則を持つ金融機関、機密システムを持つ政府機関に使用します。



NOTE: NetApp Console は制限モードとプライベート モードでデータ フローを制限しますが、環境が規制に準拠していることを確認する必要があります。

各展開モードでは、アウトバウンド接続、場所、インストール、認証、データ サービス、課金方法が異なります。

[[how-netapp-console-works-in-standard-mode]]
=== NetApp Console が標準モードでどのように動作するか

コンソールは標準モードでは次のように動作します。

アウトバウンドコミュニケーション:: エージェントから Console SaaS アプリケーション、クラウド プロバイダの公開リソース、および日常業務に不可欠なその他のコンポーネントへの接続が必要です。
+
--
* link:task-install-agent-aws-console.html#networking-aws-agent["AWS でエージェントが接続するエンドポイント"]
* link:task-install-agent-azure-console.html#networking-azure-agent["Azure でエージェントが接続するエンドポイント"]
* link:task-install-agent-google-console-gcloud.html#networking-gcp-agent["Google Cloud でエージェントが接続するエンドポイント"]


--
Console エージェントのサポートされる場所:: 標準モードでは、クラウドまたはオンプレミスに Console エージェントをインストールできます。



NOTE: クラウドにエージェントをインストールすると、クラウド使用料が発生します。

コンソールエージェントのアップグレード:: NetApp はエージェント ソフトウェアを毎月自動的にアップグレードします。
ユーザーインターフェースアクセス:: ユーザインターフェイスには、パブリックインターネット経由で利用できる Console SaaS アプリケーションからアクセスします。
APIエンドポイント:: API呼び出しは次のエンドポイントに対して行われます: \https://api.bluexp.netapp.com
認証:: NetApp Consoleは、auth0またはNetApp Support Site（NSS）ログインによる認証を提供します。アイデンティティフェデレーションが利用可能です。

[[how-netapp-console-works-in-restricted-mode]]
=== 制限モードでのNetApp Consoleの動作

制限モードではコンソールは次のように動作します。

アウトバウンドコミュニケーション:: エージェントは、データ サービス、ソフトウェア アップグレード、ユーザ認証、メタデータの転送をサポートするために、NetApp クラウドベース API へのアウトバウンド接続が必要です。
+
--
NetAppはエージェントへの通信を開始しません。エージェントはすべての通信を開始し、必要に応じてNetApp APIとサービスからデータをプルしたり、データをプッシュしたりすることができます。

リージョン内からクラウド プロバイダー リソースへの接続も必要です。

--
エージェントがサポートされる場所:: 制限モードでは、エージェントをクラウド（政府リージョン、主権リージョン、または商用リージョン）にインストールします。
コンソールエージェントのアップグレード:: NetApp Console はエージェント ソフトウェアを毎月自動的にアップグレードします。
ユーザーインターフェースアクセス:: ユーザーは、クラウド リージョンにデプロイされたエージェント仮想マシンからConsoleにアクセスします。
APIエンドポイント:: API 呼び出しはエージェント仮想マシンに対して行われます。
認証:: 認証は、auth0を使用するNetApp Consoleのクラウドサービスによって提供されます。IDフェデレーションも利用できます。




[[how-to-get-started-with-restricted-mode]]
=== 制限モードの開始方法

NetApp Console アカウントを作成するときに、制限モードを有効にする必要があります。組織がない場合は、インストールした Console エージェントに初めてログインするときに、組織を作成して制限モードを有効にするように求められます。

組織を作成した後は、制限モードの設定が固定されることに注意してください。制限モードを後から有効または無効にすることはできません。link:task-quick-start-restricted-mode.html["制限モードの開始方法を学ぶ"]。

[[how-netapp-console-works-in-private-mode]]
=== NetApp Console がプライベートモードで動作する仕組み

NetApp Console はプライベート モードでは次のように動作します：

アウトバウンドコミュニケーション:: Console SaaS アプリケーション（追加の API エンドポイントが存在する場所）への送信接続は必要ありません。すべてのパッケージ、依存関係、および必須コンポーネントは、Console エージェントとともにパッケージ化され、ローカルマシンから提供されます。Cloud Volumes ONTAP を導入する場合にのみ、クラウド プロバイダの公開リソースへの接続が必要です。
Console エージェントのサポートされる場所:: プライベートモードでは、Console エージェントはクラウドまたはオンプレミスでサポートされます。
コンソールエージェントのアップグレード:: コンソールエージェントソフトウェアは手動でアップグレードする必要があります。NetApp は、コンソールエージェントソフトウェアを不定期で NetApp Support Site に公開しています。
ユーザーインターフェースアクセス:: ユーザは、クラウド リージョンまたはオンプレミスにデプロイされた Console エージェントから Console にアクセスします。
APIエンドポイント:: API 呼び出しは、 Console エージェント仮想マシンに対して行われます。
認証:: 認証は、ローカル ユーザ管理とアクセスを通じて提供されます。認証はNetApp Consoleのクラウド サービスを通じて提供されません。
