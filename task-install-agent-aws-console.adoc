= NetApp ConsoleからAWSにConsoleエージェントをデプロイする
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs:

[role="lead"]
NetApp Consoleから離れることなくAWSにConsoleエージェントを展開し、AWSリソースとデータサービスの管理を開始できるようにします。

AWSにConsoleエージェントを展開すると、選択したVPC内でLinuxおよびConsoleエージェントソフトウェアを実行するEC2インスタンスが起動します。

.開始する前に
* link:concept-agent-install-options.html#agent-console-deploy["コンソールからいつ導入するかを確認する"]。
* レビューlink:reference-limitations.html["コンソールエージェントの制限"]。

== ステップ 1：AWSにConsoleエージェントを展開するためのネットワークを設定する

Consoleエージェントを展開する予定のネットワークロケーションが、以下の要件を満たしていることを確認してください。これらの要件により、Consoleエージェントはハイブリッドクラウド内のリソースとプロセスを管理できるようになります。

VPCとサブネット:: コンソール エージェントを作成するときは、そのエージェントが存在する VPC とサブネットを指定する必要があります。


ターゲットネットワークへの接続:: コンソール エージェントには、システムを作成および管理する予定の場所へのネットワーク接続が必要です。たとえば、オンプレミス環境にCloud Volumes ONTAPシステムまたはストレージ システムを作成する予定のネットワークなどです。


アウトバウンドインターネットアクセス:: コンソール エージェントを展開するネットワークの場所には、特定のエンドポイントに接続するための送信インターネット接続が必要です。


コンソールエージェントから接続されたエンドポイント:: コンソール エージェントは、日常業務でパブリック クラウド環境内のリソースとプロセスを管理するために、次のエンドポイントに接続するために、送信インターネット アクセスを必要とします。
+
--

+

以下の認証方法から1つを選択し、必要な設定のみを行ってください：

[cols="1a,2a,2a"]
|===
| 方法 | その機能 | 設定内容 


 a| 
*私のロールを作成してください*
 a| 
ConsoleはAWS CloudFormationのクイック作成を開き、Consoleが引き受けるデプロイロールを作成します。
 a| 
スタックを送信するAWS IDに対する権限。



 a| 
*ロールを引き受ける*
 a| 
Consoleは、お客様のアカウント内の既存のIAMロールを引き受けます。
 a| 
ポリシーとIAMロール。



 a| 
*AWSキー*
 a| 
ConsoleはAWSのアクセスキーとシークレットキーを使用します。
 a|

|===
*Create role for me* と *Assume role* を使用すると、ConsoleはConsoleエージェントをデプロイするために、*デプロイメントロール*と呼ばれるIAMロールを引き受けます。デプロイ後、Consoleエージェントは、EC2インスタンスにアタッチされた別のIAMロール（*エージェントロール*と呼ばれます）を使用します。デフォルトでは、Consoleがエージェントロールを作成します。link:#aws-agent-role["独自のエージェントロールを使用する方法"]。



[[set-up-permissions-for-create-role-for-me-cloudformation-quick-create]]
[[aws-permissions-quick-create]]
=== Create role for me（CloudFormation クイック作成）の権限を設定します

CloudFormationスタックとデプロイメントロールを作成できるAWS IDを使用して、権限エラーなしでスタックが完了するようにします。

CloudFormation Quick Createスタックを送信するIDには、管理者権限、または以下の最小限の権限が必要です。これらの権限により、CloudFormationはデプロイメントロールを作成できます。これらはエージェントロールの権限ではありません。

[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "CloudFormationStack",
      "Effect": "Allow",
      "Action": [
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:GetTemplateSummary",
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:GetRole",
        "iam:PutRolePolicy",
        "iam:DeleteRolePolicy",
        "iam:GetRolePolicy",
        "iam:PassRole",
        "lambda:CreateFunction",
        "lambda:DeleteFunction",
        "lambda:GetFunction",
        "lambda:InvokeFunction"
      ],
      "Resource": "*"
    }
  ]
}
----

[[aws-permissions-assume-role-keys]]
=== ロールの引き受けまたはAWSキーの権限を設定します

*Assume role* または *AWS keys* を選択した場合は、Consoleエージェントをデプロイするために必要な権限のみを持つポリシーを作成し、Consoleが使用するロールまたはユーザーにアタッチします。

必要に応じて、IAMを使用してIAMポリシーを制限することができます。 `Condition`要素。 https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_elements_condition.html["AWS ドキュメント: 条件要素"^]

.手順
. AWS IAM コンソールに移動します。
. *ポリシー > ポリシーの作成*を選択します。
. 「JSON」を選択します。
. 次のポリシーをコピーして貼り付けます。
+
このポリシーには、ConsoleからAWSでConsoleエージェントを起動するために必要な権限のみが含まれています。link:reference-permissions-aws.html["エージェントロールの権限を表示する"]。

+
[source, json]
----
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "iam:CreateRole",
        "iam:DeleteRole",
        "iam:PutRolePolicy",
        "iam:CreateInstanceProfile",
        "iam:DeleteRolePolicy",
        "iam:AddRoleToInstanceProfile",
        "iam:RemoveRoleFromInstanceProfile",
        "iam:DeleteInstanceProfile",
        "iam:PassRole",
        "iam:ListRoles",
        "ec2:DescribeInstanceStatus",
        "ec2:RunInstances",
        "ec2:ModifyInstanceAttribute",
        "ec2:CreateSecurityGroup",
        "ec2:DeleteSecurityGroup",
        "ec2:DescribeSecurityGroups",
        "ec2:RevokeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupEgress",
        "ec2:AuthorizeSecurityGroupIngress",
        "ec2:RevokeSecurityGroupIngress",
        "ec2:CreateNetworkInterface",
        "ec2:DescribeNetworkInterfaces",
        "ec2:DeleteNetworkInterface",
        "ec2:ModifyNetworkInterfaceAttribute",
        "ec2:DescribeSubnets",
        "ec2:DescribeVpcs",
        "ec2:DescribeDhcpOptions",
        "ec2:DescribeKeyPairs",
        "ec2:DescribeRegions",
        "ec2:DescribeInstances",
        "ec2:CreateTags",
        "ec2:DescribeImages",
        "ec2:DescribeAvailabilityZones",
        "ec2:DescribeLaunchTemplates",
        "ec2:CreateLaunchTemplate",
        "cloudformation:CreateStack",
        "cloudformation:DeleteStack",
        "cloudformation:DescribeStacks",
        "cloudformation:DescribeStackEvents",
        "cloudformation:ValidateTemplate",
        "ec2:AssociateIamInstanceProfile",
        "ec2:DescribeIamInstanceProfileAssociations",
        "ec2:DisassociateIamInstanceProfile",
        "iam:GetRole",
        "iam:TagRole",
        "kms:ListAliases",
        "cloudformation:ListStacks"
      ],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": [
        "ec2:TerminateInstances"
      ],
      "Condition": {
        "StringLike": {
          "ec2:ResourceTag/OCCMInstance": "*"
        }
      },
      "Resource": [
        "arn:aws:ec2:*:*:instance/*"
      ]
    }
  ]
}
----
. 必要に応じて、[次へ] を選択し、タグを追加します。
. *次へ*を選択し、名前と説明を入力します。
. *ポリシーの作成*を選択します。
. コンソールが引き受けることができる IAM ロールまたは IAM ユーザーにポリシーをアタッチして、コンソールにアクセスキーを提供できるようにします。
+
** *ロールの引き受け*：Consoleが引き受けることができるIAMロールを設定します：
+
... ターゲットアカウントの AWS IAM コンソールに移動します。
... [アクセス管理] で、*[ロール] > [ロールの作成]* を選択し、手順に従ってロールを作成します。
... *信頼されたエンティティタイプ*で、*AWS アカウント*を選択します。
... *別のAWSアカウント*を選択し、コンソールSaaSアカウントのIDを入力します: 952013314444
... 前のセクションで作成したポリシーを選択します。
... ロールを作成したら、コンソール エージェントを作成するときにコンソールに貼り付けることができるように、ロール ARN をコピーします。


** *AWSキー*：Consoleにアクセスキーを提供できるように、IAMユーザーの権限を設定します：
+
... AWS IAM コンソールから [*ユーザー*] を選択し、ユーザー名を選択します。
... *権限の追加 > 既存のポリシーを直接添付*を選択します。
... 作成したポリシーを選択します。
... *次へ*を選択し、*権限の追加*を選択します。
... IAM ユーザーのアクセスキーとシークレットキーがあることを確認します。






.結果
これで、必要な権限を持つデプロイメントロールまたはIAMユーザーが作成されました。Consoleエージェントをデプロイする際、ロールARNまたはアクセスキーを指定します。



[[step-3-set-up-your-own-iam-role-for-the-console-agent-optional]]
[[aws-agent-role]]
== ステップ3：Consoleエージェント用の独自のIAMロールをセットアップする（オプション）

Consoleがデフォルトで作成するロールの代わりに独自のロールを選択する場合は、独自のエージェントロールを作成してください。Consoleエージェントをデプロイする前に、ロールを作成してください。

.手順
. AWS コンソールにログインし、IAM サービスに移動します。
. ポリシーを作成します。
+
.. *ポリシー > ポリシーの作成*を選択します。
.. *JSON*を選択し、その内容をコピーして貼り付けます。link:reference-permissions-aws.html["コンソールエージェントのIAMポリシー"] 。
.. 残りの手順を完了してポリシーを作成します。
+
標準リージョンの場合、権限は 2 つのポリシーに分散されます。 AWS の管理ポリシーの最大文字サイズ制限により、2 つのポリシーが必要になります。link:reference-permissions-aws.html["コンソールエージェントのIAMポリシーの詳細"] 。



. IAM ロールを作成します。
+
.. *[ロール] > [ロールの作成]*を選択します。
.. *AWS サービス > EC2* を選択します。
.. 作成したポリシーを添付して権限を追加します。
.. 残りの手順を完了してロールを作成します。




.結果
これで、Consoleエージェントを展開する際に、*エージェント展開の詳細*で選択できるエージェントの役割ができました。



[[step-4-deploy-the-console-agent]]
== ステップ4：Consoleエージェントを展開する

ConsoleがVPC内でConsoleエージェントを起動できるように、認証、デプロイ、ネットワーク、およびセキュリティグループの詳細を指定してください。

.タスク概要
* コンソールからコンソール エージェントを作成すると、デフォルト設定を使用して AWS に EC2 インスタンスがデプロイされます。コンソールエージェントを作成した後、CPU や RAM が少ない小さな EC2 インスタンスに切り替えないでください。link:reference-agent-default-config.html["コンソールエージェントのデフォルト構成について学習します"] 。
* デフォルトでは、Consoleはエージェントロールとそのプロファイルを作成します。独自のエージェントロールを提供する場合は、今後のリリースで新しい権限が追加されるたびに、そのロールを更新するようにしてください。link:reference-permissions-aws.html["コンソールエージェントのIAMポリシーの詳細"]。


.開始する前に
次のものが必要です:

* AWS認証方法：*自分用のロールを作成する*、*ロールを引き受ける*、または*AWSキー*。
* ネットワーク要件を満たす VPC とサブネット。
* EC2 インスタンスのキーペア。
* コンソール エージェントからのインターネット アクセスにプロキシが必要な場合のプロキシ サーバーの詳細。
* 完了 link:#networking-aws-agent["ステップ1"]。
* 完了 link:#aws-permissions-agent["ステップ2"]。


.手順
. *管理 > エージェント*を選択します。
. *概要*ページで、*エージェントのデプロイ > AWS*を選択します。
. 「エージェントデプロイ用のAWS認証情報」セクションで、以下の認証方法のいずれかを選択してください：
+
** *ロールを作成*：
+
... AWSリージョンを選択し、AWSアカウントIDを入力してください。必要に応じて、外部IDを入力してください。
... *CloudFormation クイック作成を開く*を選択します。
... AWSでは、利用規約に同意して「スタックの作成」を選択します。
... AWSがロールの作成を完了したら、Consoleに戻り、ロールを確認します。


** *ロールを引き受ける*：IAMロールのARNを入力し、*認証情報の検証*を選択します。
** *AWSキー*：アクセスキーとシークレットキーを入力し、*認証情報の検証*を選択します。


. *エージェント展開の詳細*セクションで、Consoleエージェントに関する詳細を指定します。
+
** 名前を入力してください。
** カスタム タグ (メタデータ) を追加します。
** Consoleにエージェントロールを作成させるか、お客様がlink:#aws-agent-role["自分で設定する"]エージェントロールを選択するかを選択してください。
** コンソール エージェントの EBS ディスクを暗号化するかどうかを選択します。デフォルトの暗号化キーを使用するか、カスタム キーを使用するかを選択できます。


. *ネットワーク構成*セクションで、Consoleエージェント用のVPC、サブネット、キーペアを指定し、パブリックIPアドレスを有効にするかどうかを選択して、必要に応じてプロキシ構成を指定します。
+
コンソール エージェント仮想マシンにアクセスするための正しいキー ペアがあることを確認します。キーペアがないとアクセスできません。

. *セキュリティグループ*セクションで、新しいセキュリティグループを作成するか、必要なインバウンドルールとアウトバウンドルールを許可する既存のセキュリティグループを選択するかを選択します。
+
link:reference-ports-aws.html["AWS のセキュリティグループルールを表示する"] 。



. 選択内容を確認し、セットアップが正しいことを確認してください。
+
.. *エージェント構成を検証する*チェックボックスは、デフォルトで選択されており、デプロイ時にNetApp Consoleがネットワーク接続要件を検証するようになっています。NetApp Consoleがエージェントのデプロイに失敗した場合、トラブルシューティングに役立つレポートが提供されます。デプロイが成功した場合、レポートは提供されません。


+
[NOTE]
====
** エージェントのアップグレードに使用されるlink:reference-networking-saas-console-previous.html["以前のエンドポイント"]をまだ使用している場合、検証はエラーで失敗します。これを回避するには、チェックボックスをオフにして検証チェックをスキップしてください。
** インストール中、NetAppは、エージェントホストに、ディスク全体の空き容量の少なくとも80パーセントがあることを確認します。これには、 `/opt`に48 GB、 `/var`に32 GBが含まれます（合計80 GB）。インストール後、ディスク全体の少なくとも20パーセントが利用可能である必要があり、これには、 `/opt`に12 GB、 `/var`に8 GBが含まれます（合計20 GB）。


====
. *追加*を選択します。
+
Consoleは、約10分でConsoleエージェントを展開します。処理が完了するまで、このページを開いたままお待ちください。



.結果
プロセスが完了すると、コンソール エージェントはコンソールから使用できるようになります。

== 失敗したConsoleエージェント展開のトラブルシューティング

デプロイメントレポートを使用してConsoleエージェントのデプロイをブロックした原因を確認し、再試行してください。

Consoleは、「エージェント構成の検証」チェックボックスが選択されている場合にのみレポートを提供します。デプロイが成功した場合、レポートは生成されません。

.手順
. *エージェントの展開に失敗しました*ダイアログボックスで、*レポートをダウンロード*を選択します。
+
Consoleは、検証レポートを含むPDFファイルをダウンロードします。

. レポートを確認し、記載されている問題を修正してください。
. ダイアログボックスで「最初からやり直す」を選択し、再度デプロイを完了してください。
+
もう一度試すには、最初からすべての手順をやり直す必要があります。
