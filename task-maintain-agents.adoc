= NetApp ConsoleエージェントVMの保守
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
手動でインストールしたエージェントにOSセキュリティアップデートを適用したり、CPU、RAM、ディスク容量のアラートに対応したり、必要に応じてVMのサイズ変更や停止、起動を行ったりして、NetApp ConsoleエージェントVMを保守します。

コンソールエージェントを手動でインストールする場合、エージェントホスト上のオペレーティングシステムの維持管理は、お客様の責任となります。たとえば、お客様は、自社のオペレーティングシステム配布に関する標準手順に従って、エージェントホスト上のオペレーティングシステムにセキュリティアップデートを適用する必要があります。

エージェントVMのリソースが不足したり、パフォーマンスの問題が発生した場合は、VMリソースをアップグレードするための適切な措置を講じる必要があります。


NOTE: vCenterにエージェントをインストールした場合は、コンソールメンテナンスツールを使用してVMインスタンスのサイズを変更します。link:task-agent-vm-config.html["vCenter でエージェント VM を保守する方法"^]。



[[apply-operating-system-updates-to-the-manually-installed-agent-hosts]]
== 手動でインストールしたエージェントホストにオペレーティングシステムのアップデートを適用します

エージェント ホスト サービスを停止せずに OS セキュリティ パッチを適用します。

サポートされている構成との互換性を維持するため、定期的なOSパッチ適用時にDockerまたはPodmanがアップグレードされないようにしてください。これは、アップデート時にDockerまたはPodmanを一時的に除外するか、パッケージマネージャーを永続的に設定してDockerまたはPodmanのアップデートをスキップすることで実現できます。

以下は、さまざまなLinuxディストリビューションでDockerまたはPodmanのアップデートを除外する方法の例です。パッケージをアップデートから除外する方法に関する最新の手順については、お使いのLinuxディストリビューションのドキュメントを参照してください。

.Podmanの例
[source, bash]
----
sudo yum update --exclude=podman
sudo yum upgrade
----
.Dockerの例
[source, bash]
----
sudo apt-mark hold docker-ce docker-ce-cli containerd.io
sudo apt update
sudo apt upgrade
----


[[resizing-the-vm-or-instance-type]]
== VMまたはインスタンスタイプのサイズ変更

コンソールからコンソール エージェントを作成すると、デフォルトの構成でクラウド プロバイダーに VM インスタンスがデプロイされます。エージェントを作成した後は、CPU や RAM が少ない小さな VM インスタンスに切り替えないでください。

エージェントVMのプロビジョニングが不足しているという通知を受け取った場合は、最適なパフォーマンスを確保するために、より多くのCPUまたはRAMを備えた大規模なVMインスタンスへのアップグレードをご検討ください。


NOTE: エージェントを VCenter にインストールした場合は、コンソールメンテナンスツールを使用してVMインスタンスのサイズを変更します。link:task-agent-vm-config.html["VCenterでエージェントVMのサイズを変更する方法"^]。

link:reference-agent-default-config.html["エージェントのデフォルト設定について学ぶ"] 。

エージェントVMのCPUまたはRAMを増やす必要がある場合は、クラウド プロバイダまたはオンプレミスの仮想化プラットフォームが提供する手順に従って、VMインスタンスのサイズを変更してください。NetAppは、最適なパフォーマンスを確保するために、現在のCPUとRAMの割り当てを2倍にすることを推奨しています。以下の表は推奨されるサイジング階層を示しており、各階層は前の階層のCPUとRAMの2倍になっています。

[cols="1,1,1"]
|===
| 階層 | CPU（コア数またはvCPU数） | RAM 


| 最小 | 8 | 32 GB 


| 中 | 16 | 64 GB 


| 大規模 | 32 | 128 GB 
|===

== エージェントを監視する

コンソールは、ディスク容量、RAM、CPU の問題など、エージェント VM に異常がある場合に通知します。コンソール内の通知センターでこれらの通知を監視するか、電子メール通知を構成します。ディスク容量、メモリ、CPU 使用率が時々増加するのは正常ですが、頻繁に発生する場合は、解決するための手順を実行する必要があります。

たとえば、エージェント リソース (CPU、RAM、またはディスク領域) が 30 分間連続して合計容量の 90% を超えると、コンソールから通知が届きます。その後、リソース使用量がそのしきい値を下回ると、通知センターに通知が解決済み (緑) として表示されます。


NOTE: エージェントVMの変更に関してご質問がある場合は、NetAppサポートにお問い合わせください。

link:https://docs.netapp.com/us-en/console-setup-admin/task-monitor-cm-operations.html#notification-center["詳細情報"^]

== Linux VMに接続する

エージェントが実行される Linux VM に接続する必要がある場合は、クラウド プロバイダーの接続オプションを使用します。

AWS:: AWS でエージェントインスタンスを作成するときは、AWS アクセスキーとシークレットキーを指定します。このキー ペアを使用してインスタンスに SSH 接続できます。  EC2 Linux インスタンスにはユーザー名「ubuntu」を使用します。  2023 年 5 月より前に作成されたエージェントの場合は、ユーザー名「ec2-user」を使用します。
+
--
https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/AccessingInstances.html["AWS ドキュメント: Linux インスタンスに接続する"^]

--
Azure:: Azure でエージェント VM を作成するときは、ユーザー名を指定し、パスワードまたは SSH 公開キーで認証することを選択します。  VM に接続するために選択した認証方法を使用します。
+
--
https://docs.microsoft.com/en-us/azure/virtual-machines/linux/mac-create-ssh-keys#ssh-into-your-vm["Azure ドキュメント: VM への SSH 接続"^]

--
Google Cloud:: Google Cloud でエージェントを作成するときに認証方法を指定することはできません。ただし、Google Cloud Console または Google Cloud CLI (gcloud) を使用して Linux VM インスタンスに接続できます。
+
--
https://cloud.google.com/compute/docs/instances/connecting-to-instance["Google Cloud ドキュメント: Linux VM への接続"^]

--
