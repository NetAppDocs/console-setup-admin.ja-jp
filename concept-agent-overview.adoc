= NetApp Consoleエージェントについて学ぶ

:allow-uri-read: 
:nofooter: 
:icons: font

:imagesdir: ./media/


[role="lead"]
Consoleエージェントを導入することで、NetApp Consoleの機能を有効化します。Consoleエージェントは、オンプレミスおよびクラウドストレージシステムとNetApp Console間の安全な接続を提供する軽量なソフトウェアコンポーネントであり、高度なストレージオーケストレーションやデータサービスを可能にします。



== コンソールエージェントの機能

コンソールエージェントは、ストレージシステムとNetApp Consoleの間のネットワークギャップを橋渡しします。インフラストラクチャをNetApp APIとConsoleに安全に接続し、次のことが可能になります：

* AWS、Azure、Google Cloud、およびオンプレミス環境全体のストレージ システムをNetApp Consoleから検出および監視します。
* NetApp Console からストレージ システム上のストレージ プロビジョニングと設定タスクをオーケストレーションします。
* 高度なデータ保護および最適化サービスを有効にします。
* クラウド プロバイダの認証情報を Console エージェントに関連付けて、クラウド サービスの使用状況を安全に追跡し、デプロイメントを適切なサブスクリプションに接続することで、正確な課金とコスト管理を実現します。




=== エージェント アーキテクチャ

エージェントは次のような軽量プロセスで動作します：

* Console SaaS アプリケーションとの間でデータをプルまたはプッシュする（標準モードと制限モード）、または完全にローカルで操作する（プライベート モード）
* すべての通信を開始します。NetApp Consoleはエージェントへの発信通話を開始しません。
* 標準管理プロトコルを使用してストレージ システムに接続します
* クラウド プロバイダおよびNetApp Console APIとの安全な通信にはTLS 1.3を使用してください




=== エージェントの可用性と運用要件

コンソールエージェントは、NetApp Consoleの重要なインフラストラクチャです。NetApp Consoleは短時間の停止に対処できますが、中断のない管理とデータ サービスを実現するために、エージェントは動作を継続し、アクセス可能な状態である必要があります。以下の事項を確実に実施する責任はお客様にあります：

* エージェントは稼働し続けます
* エージェントには、必要なエンドポイントへのネットワーク接続があります
* インフラの障害はすぐに解決される
* エージェント VM は、NetApp の推奨事項に従って保守およびアップグレードされます




== Console エージェントが必要な場合

以下の場合には、少なくとも 1 つの Console エージェントを展開する必要があります：

* 制限付きまたはプライベートな展開モードを使用します（Console は独自の環境にインストールされます）。一部のサービスを有効にするには追加のエージェントが必要です。
* 高度なデータサービスにアクセス（NetApp Backup and Recovery、NetApp Disaster Recovery、NetApp Ransomware Resilience、NetApp Data Classification など）。
* Cloud Volumes ONTAPシステムを管理します。
* オンプレミス ONTAP クラスタで高度な管理タスクを実行します。
* ライセンスを追跡し、ストレージの健全性を監視し、ライフサイクルのアップグレードを計画します。


エージェントがなくても、基本的なストレージ検出を実行し、監視機能とストレージ管理機能の限定されたセットにアクセスできます。ただし、ほとんどのエンタープライズ ユース ケースでは、1 つ以上の運用エージェントが必要です。

link:concept-modes.html["NetApp Consoleの導入モードについて学ぶ"]エージェントが必要な状況とエージェントによって実現される機能を理解します。



== Console エージェントの導入オプション

Console エージェントは次の場所に導入できます：

* Amazon Web Services（標準、制限、またはプライベートモード）
* Microsoft Azure（標準、制限、またはプライベート モード）
* Google Cloud（標準、制限付き、またはプライベートモード）
* お客様の環境内（標準モードまたはプライベートモード）


NetApp Consoleの導入モード、ストレージ環境、およびデータ主権のニーズによって、エージェントを導入する場所が決まります。組織の分離やビジネスニーズに応じて、環境全体に複数のエージェントを導入します。

エージェントを展開したら、NetApp Console組織に登録して、その組織の機能を有効にします。複数のストレージ システムとデータ サービスを単一のエージェントに関連付けたり、組織の分離やビジネス ニーズに合わせて複数のエージェントを環境全体に展開したりすることができます。



=== NetApp Console SaaS アプリケーション（標準モード）のエージェント

クラウドまたはオンプレミスにエージェントを導入して、クラウドでホストされる Console SaaS アプリケーションへの接続をブリッジします。エージェントは高度な機能を有効にしますが、Console UI はどこからでもアクセスできます。

SaaS アプリケーション（標準モード）を使用する場合、Console から直接エージェントをインストールできます。AWS、Azure、Google Cloud にインストールすることも、オンプレミスの Linux ホストまたは VCenter 環境に手動でインストールすることもできます。

エージェントをオンプレミスにインストールする場合、それぞれのクラウド プロバイダの資格情報を関連付けて、課金統合とデータ サービスを有効にすることができます。



=== 制限モードのNetApp ConsoleのエージェントNetApp

ユーザーがNetApp Consoleにアクセスするために、1つのエージェントをインストールする必要があります。データ サービスを有効にし、ストレージ システムを管理するには、追加のエージェントが必要です。

制限モードでNetApp Consoleを使用している場合は、クラウド プロバイダのマーケットプレイスからエージェントをインストールするか、クラウド内、オンプレミス、またはVCenter環境内の独自のLinuxホストにソフトウェアを手動でインストールします。

ユーザーがNetApp Consoleにアクセスするために、1つのエージェントをインストールする必要があります。データ サービスを有効にし、ストレージ システムを管理するには、追加のエージェントが必要です。

=== プライベートモードのNetApp Console用エージェント（オンプレミスまたはアウトバウンド接続のないクラウド内）

ユーザーがNetApp Consoleにアクセスするために、1つのエージェントをインストールする必要があります。データ サービスを有効にし、ストレージ システムを管理するには、追加のエージェントが必要です。

データ センターまたはエアギャップ環境にエージェントをインストールします。エージェントはNetApp API エンドポイントに接続できません。すべての操作はローカルで実行され、完全なデータ主権と制御が維持されます。

ユーザーがNetApp Consoleにアクセスするために、1つのエージェントをインストールする必要があります。データ サービスを有効にし、ストレージ システムを管理するには、追加のエージェントが必要です。

エージェントをオンプレミスにインストールする場合、それぞれのクラウド プロバイダの資格情報を関連付けて、課金統合とデータ サービスを有効にすることができます。



=== 必要に応じて複数のエージェントを使用する

各エージェントは独立して動作し、複数のストレージ システムとデータ サービスを管理できます。次の場合は複数のエージェントを導入します：

* ストレージ タイプまたは組織機能による分離
* 地理的またはネットワークのセグメンテーション要件を満たす
